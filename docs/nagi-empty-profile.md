# プロフィール未設定の Nagi ユーザー

`com.suibari.nagi.profile/self` がなくても、Nagi 投稿を持つ人はプロフィール未設定の
Nagi ユーザーとして扱う。外部アプリから初めて投稿した人と、プロフィールレコードだけを
削除した人のどちらにも適用する。プロフィール削除は退会ではない。

- 投稿の取り込み、公開範囲、モデレーション、bot 返信条件は通常の投稿と同じ。
- DID・ハンドルを本人識別に使用する。Bluesky の表示名・自己紹介・画像は補完しない。
- PDS や AppView に空のプロフィールを自動作成しない。投稿だけでプロフィール作成時の
  自動分析を起動しない。
- API はプロフィール由来の情報を省略する。ハンドル解決前は DID を返す。
- プロフィールページは投稿があれば取得できる。参加日時はプロフィール作成日時、
  プロフィールがなければ初投稿日を使用する。
- ユーザー検索は active な actor のうち、プロフィールまたは削除されていない投稿が
  ある人を対象とする。プロフィール未設定でも exact/hybrid でハンドル検索できる。
  意味検索には既存のプロフィール埋め込みを使用する。
- プロフィールを削除しても投稿は残る。再作成すると、新しいプロフィール情報が反映される。

## クライアントの表示確認

画面側は別管理。表示名がなければハンドル、アバターがなければ既定アイコンを表示し、
自己紹介は未設定として扱う。投稿カード・プロフィール画面・検索結果について、
プロフィールのない投稿者とプロフィールを削除した投稿者の両方を確認する。

## PostgreSQL 回帰テスト

専用の使い捨て DB `nagi_profile_test`（pgvector 必須）に対して実行する。
テストは対象テーブルを空にするため、アプリの DB を指定しない。

```sh
NAGI_PROFILE_TEST_DATABASE_URL=postgres://USER:PASS@HOST:PORT/nagi_profile_test \
  pnpm exec tsx --test apps/nagi_appview/test/emptyProfile.postgres.test.ts
```

環境変数未設定時は DB テストをスキップする。新しいスキーマやデータ移行は不要。
