# 感情グラフ（Mood graph） 設計メモ

Nagi のメニューの「日記」を「アクティビティ」ページに改め、「日記」「感情グラフ」「年表」の3タブにした。
URL は通知の `/diary?date=` と互換のため `/diary` のまま。
投稿ごとに書き手の気分を -5〜+5 で読み取り、日ごとの**幅**として1年分を並べる。
日付を押すと、その日の投稿（スコア付き）と日記を開く。グラフの外を押すか Esc で閉じる。

本書は決定事項と**その理由**を残す（`docs/chronicle.md` と同じ位置づけ）。

---

## 1. 何を見せるか

- **帯は気分の値で色を付ける。** 縦のグラデーション（-5 紫 → 青 → 0 緑 → 黄 → +5 オレンジ）を
  グラフ全体に1本張るので、帯の色がそのまま値の高さを表す。値が1つしかない日は丸で出す。
- **1日の平均ではなく幅。** 同じ日に明るい投稿と沈んだ投稿が混ざるのが普通で、平均すると
  0 付近に潰れて何も見えなくなる。帯は**中央50%**（第1〜第3四分位）で、線は中央値。
  最小〜最大の帯は PoC で試したが、外れ値1件でほぼ毎日が全幅になり情報が無かった。
- **中立の投稿は入れない。** 告知・機能説明・事実の共有など、気分が読み取れない投稿
  （`expressive=false`）は帯にも一覧にも含めない。含めると中央値が 0 に張り付く。
- **投稿ごとの点は描かない。** 本人確認済み（2026-09-26）。点は帯と重なって流れが読みにくくなる。
  個々の投稿は、日付を押したときの一覧で見る。
- **開発報告とイラスト投稿は中立のまま。** 本人確認済み（2026-09-26）。画像はモデルに渡していない。
- **採点の理由は出さない。** PoC では確認用に出したが、本実装ではスコアと本文だけ。
- 評価語（「よい」「悪い」）は使わず、「明るい」「沈んだ」で言う。本人だけが見る。

## 2. 1日の区切り

グラフの1日は**日記と同じ「前日22時の直後〜当日22時」**（`diaryInteractionWindow`）。
暦日で切ると、グラフで押した日と開く日記の材料がずれる。タイムゾーンは日記と同じく言語から決める
（最新の日記の言語、日記が無ければ最新の投稿の言語）。振り分けは AppView の `moodDiaryDate`。

## 3. 採点

- `packages/bot_brain/src/ai/scorePostMood.ts`。機能キー `NAGI_POST_MOOD`（ローカル Ollama 固定）。
  投稿1件ずつ、temperature 0、JSON 構造化出力（`valence` と `expressive` だけ）。
- 保存先は `nagi.post_moods`（posts の列にしない。取り込み経路を触らずに済み、
  編集は cid の不一致、基準の変更は `POST_MOOD_VERSION` の不一致として拾い直せる）。
- `NagiPostMoodWorker` が「採点なし／cid 違い／版違い」の投稿を**新しい順に**1分ごと24件まで採点する。
  過去分のバックフィルもこのワーカーが兼ねる。**botたん自身の投稿（`NAGI_BOT_DID`）は対象外。**
  開発DBでは投稿の半分以上（4,964件中2,811件）が bot の返信で、除かないと採点時間の大半を食う。
  早く埋めたいときは `pnpm --filter nagi-bot-server mood:backfill`（DID を渡すとその1人だけ）。
- Ollama の接続失敗はその tick を打ち切って保存しない。本文が空・出力が壊れているものは
  `valence=null` で保存し、同じ投稿で叩き続けない。

## 4. API

新しい XRPC は作らず、**`getDiaries` の期間指定に `moods=true` を付けたときだけ**
`moods`（点の配列）と `moodPending`（未採点数）を返す。新しいメソッドを足すと
OAuth の permission set の再公開と全員の再認可が要るため。日記と同じく本人以外には 403。

## 5. PoC（2026-09-25、suibari.com の投稿 426件）

| 版 | 方針 | 分布（-5〜+5） |
|---|---|---|
| v1 | 目安を奇数段だけに書いた | +3 が 123件、+2 が 17件。告知や開発メモが熱意で +3 に寄った |
| v2（採用） | 全段に目安、告知・説明は 0〜+1、ネタは ±2 以内 | +3 が 31件、+2 が 108件、-2 が 41件 |

- 深い落ち込み（「仕事やめたい」→ -5）と強い喜び（「UR引いた！！」）はどちらの版でも拾えた。
- 残る誤読: ネタの読み違い（「やったか！？（フラグ）」→ -3）。
- 本実装では出力から `reason` を外した（プロンプトの1行も減る）。同じ投稿で比べると
  27件中7件が ±1〜2 ずれた。ずれの向きに偏りは無かった。

## 6. デプロイ

1. `pnpm --filter @bsky-affirmative-bot/database drizzle:push`（`nagi.post_moods` の作成。
   手動なら `packages/database/drizzle/0081_nagi_post_moods.sql`）
2. AppView と nagi-bot を再起動。ワーカーが自動でバックフィルを始める
   （実測 約52件/分。開発DBの利用者の投稿 約2,150件で40分ほど）。
3. クライアント（nagi_client）を出す。バックフィル中はグラフの下に未採点数が出る。
