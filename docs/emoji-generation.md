# 絵文字の生成

Nagi のカスタム絵文字（Bluemoji）を、本人のプロンプトから GPU 機の imggen（MOSS-Image）で描く。
設計の経緯と検証結果は nagi_client の `docs/emoji-generation-design.md`。

## 流れ

```
Nagi クライアント ──(PDS プロキシ)──▶ AppView ──(LAN)──▶ imggen サイドカー ──▶ ComfyUI / MOSS
  依頼・一覧・候補選択・登録         受付・ジョブ（DB）・結果保存       描画・クロマキー抜き・128px化
```

1. `com.suibari.nagi.createEmojiGeneration` でプロンプトを1つ送る（モードは選ばせない）。受付時に
   プロンプトをモデレーションに通し、gemma で「何を描くか（英文）」「書く文字」「縦横比」と、
   登録名・説明の案に分ける
   （ワーカーの時点で Ollama を呼ぶと、ComfyUI が VRAM を使っている最中のことがあり、OOM の引き金になる）。
2. `nagi.emoji_generations` に積む。未完了は1人1件（部分一意索引）。全体の待ちは
   `NAGI_EMOJI_GENERATION_QUEUE_LIMIT` まで。
3. ワーカー（5秒ごと）が1枚描く（30〜45秒、ComfyUI の起動が乗ると倍）。気に入らなければ本人が頼み直す。
   3枚描いて選ばせる案は、待ちが数分になり GPU を bot と取り合う時間も3倍になるのでやめた。
4. 描き終えたら結果を保存する。完了通知・プッシュは送らず、本人が生成画面で確認する。その人の前の結果は消す（画面は最新の1件だけを見せ、描き直し中は
   前の絵の上にスピナーを出す）。残るのは最新の結果1件と、描いている途中の依頼1件まで。候補は1日で消える（登録した絵文字は PDS にあるので困らない）。
5. 本人は候補の「登録」を押すだけ。名前と説明は gemma の案をそのまま使い、クライアントのいつもの
   絵文字登録で PDS に書く（`ai-generated` セルフラベル付き。絵文字名は重複してよい）。

## 描き方（`services/emojiGenerationPrompt.ts`）

- gemma がプロンプトを分ける。「それな」「草」のような短い言葉は書く文字に、「ガッツポーズする
  ペンギン」は描く内容になる。解釈がずれても、botたんが描くものなのでご愛敬とする。
- 書く文字があれば縦横比は文字数で決まる（1〜2文字 768² ／ 3〜4文字 1088×544 ／ 5文字以上 1280×448）。
  10文字を超える文字は書かせない。無ければ gemma の判断で square か wide。
- 日本語のまま MOSS に渡すと修飾や動作が落ちる（三毛→茶白など）ので、描く内容は英文にする。
  書く文字は訳さない（MOSS は日本語の文字を6文字まで誤字なしで描けた）。
- botたん・ラテちゃん・ことみちゃん・モルフォの名前が出てきたら、bot の絵と同じ見た目の文
  （shared-configs の `mossCharacters.ts`。bot-tan-imagegen の `promptConfig.json` の `moss.characters` と
  同じく見た目と服を分けて持つ）を描画の指示に足す。gemma も MOSS もこの子たちを知らないため。
- 服は gemma がプロンプトから判定する（none / uniform / casual / pajamas / swimsuit / other）。
  指定が無ければ署名の1着（botたんは制服、ラテちゃんはメイド服、ことみちゃんはアイドル衣装）。
  決まった服をそのキャラが持っていれば差し替え（パジャマのbotたん、制服のことみちゃん）、
  持っていない服（水着のラテちゃん）や決まった服以外（サンタ服など）は、キャラの文から服を外して
  subject に書かれた服に任せる。服を固定したままだと、指定と食い違って運次第になる。
- 画風は bot と同じ suibari LoRA（重み 1.0）。文字だけの絵文字に顔などが描き足されることがあるが許容する。
- 画風・背景・構図は固定し、入力は「何を描くか」だけに入る。
- 背景はクロマキー（マゼンタ。入力にピンク・紫などがあれば緑）。サイドカーの `cutout` が抜いて
  128px の透過 PNG にし、`conflict`（被写体がキー色に近くて面ごと半透明になった度合い）を返す。
  0.05 を超えたら、もう一方のキー色で1回だけ撮り直す。
- スタイル（二重縁取り・キラキラ・手書き風）は描くたびにくじで選ぶ。シードを変えても構図・色がほぼ同じ
  だったので、頼み直したときに違う絵になるよう文で変える。

## GPU の同居

5070 Ti を bot の Ollama（gemma-4-12B）と Irodori-TTS と共有する。MOSS の速度は落とさないので
VRAM に上限は設けず、OOM で Ollama が CPU 混在になったら GPU 機の ollama-recovery
（docs/ollama-recovery.md）が載せ直す前提にする。ワーカーは次を守る。

- 1枚ごとに Ollama の `/api/ps` を見て、全モデルが全層 GPU に載っていなければ描かない。
  そのとき ComfyUI を降ろす（載っていると ollama-recovery が載せ直せない）。
- 待ちが無くなったらすぐサイドカーの `/unload` を呼び、VRAM と RAM（ComfyUI は RSS 約13GB）を返す。
- 1時間に描く枚数を `NAGI_EMOJI_GENERATION_HOURLY_LIMIT` で絞る（全体の安全弁）。
- ollama-recovery が連続失敗で止まっている（heartbeat の recovery が blocked）間は受け付けない。
- ollama-recovery は、混在のときに imggen が直前まで使われていて今は降りていれば、30分の再試行間隔を
  待たずに載せ直す。

2026-10-28 の検証では、ComfyUI が空き VRAM をほぼ使い切っている最中に Ollama が計算バッファ 311MB を
追加で確保しようとして OOM になり、モデルを降ろした。そこへ ComfyUI がすぐ立ち上がり直したため、
読み直しが49層中11層しか GPU に載らず、約4分続いた。
